# CountAway 1.1.8

CountAway 1.1.8 makes recurring dates practical while tightening the local data, reminder, widget, accessibility, and release paths around them.

## New

- Countdowns can repeat yearly across the app, widgets, native sharing, backups, and reminders.
- Yearly countdowns automatically move to their next occurrence, including February 29 falling back to February 28 in non-leap years.
- A saved countdown can request a home-screen widget directly on launchers that support Android widget pinning.

## Improved

- Backups and local storage recover more safely from interrupted writes, malformed data, future schemas, extreme dates, and stale editor state.
- Imports remain bound to the exact backup snapshot that was reviewed, while historical CountAway backups remain restorable without silent truncation.
- Reminder state reacts consistently to date, time, timezone, permission, channel, edit, delete, and restore changes, with bounded retries instead of retry loops.
- Widgets follow the real System theme, restore per-widget preferences across host ID remapping, batch shared data work, and adapt across compact, wide-short, standard, and large sizes.
- Editor and list layouts handle larger text and IME insets more gracefully, with stronger text contrast and unsaved-draft protection.
- Functional locale selection now scans the effective system locale list correctly.

## Release integrity

- Release candidates are bound to an explicit source SHA and retain validation evidence.
- An independent runner rebuilds the same unsigned release APK and must produce the same SHA-256.
- The final APK is checked for the expected package/version, signing certificate, permission surface, SDK levels, absence of runtime dependencies/native code, R8 mapping, and resource shrinking.
- Stable public release assets are protected from replacement by different bytes.
- Stable preparation is blocked until CountAway is demonstrably published by official F-Droid with a downloadable APK using the expected signing identity.

No new runtime permissions, accounts, network access, analytics, cloud synchronization, runtime dependencies, exact alarms, foreground services, or permanent services.
